# M04.17C — Escrita de comparativo no WordPress (via MCP)

**Sem merge, sem deploy, sem publicação, sem escrita no WordPress.**

## 1. Auditoria do `wp_publisher`: qual é o caminho efetivo

| Fato | Onde |
|---|---|
| A publicação vai por `POST {wp_url}/wp-json/wp/v2/posts` | `wp_publisher.py:156` |
| O tipo é **sempre `post`** — o endpoint `posts` fixa o `post_type` | idem |
| O payload é `title`/`content`/`status` (+ categorias, tags, media, slug) | `wp_publisher.py:140-152` |
| O gate de publish: `publish` só com `status_validacao == PASS`; senão força `draft` | `wp_publisher.py:100-107` |
| Quem chama: `pipeline_rss.py:130` (sempre `status_desejado="draft"`) e `pipeline_p0.py:170` (`"publish" if args.publish else "draft"`) | — |
| **Não existe cliente MCP no MKT-RSS** | varredura: nenhuma ocorrência de `mcp`/`conexo/v1` no repositório |

Ou seja: o caminho efetivo é REST puro, tipo `post`, sem qualquer noção de
comparativo.

## 2. Por que o comparativo NÃO pode ir pelo REST

O CPT `comparativo` é registrado (`conexotech/functions.php:86`) com
`show_in_rest => true` — **mas sem `meta`**. Consequência: os campos
`_conexo_prod_*`, `_conexo_nota_*`, `_conexo_buy_*` e `_conexo_crit_*`
**não são graváveis pelo REST**.

E o template depende deles: `single-comparativo.php` lê `_conexo_prod_1`,
`_conexo_nota_1`, `_conexo_buy_1` e `_conexo_crit_{r}_label/_v1..3/_win` para
montar a tabela. Um comparativo criado por `POST /wp/v2/comparativo` nasceria
**sem a tabela** — um post quebrado, com o pior defeito possível: parecer
publicado e não ser.

Quem escreve esses campos é o servidor MCP, no PHP
(`conexo_mcp_tool_create_comparativo`, `inc-mcp-server.php:279`).

## 3. A solução: cliente MCP mínimo, sem dependência nova

Duas funções novas em `mkt_flow_p0/wp_publisher.py` (as legadas ficam
**byte-idênticas** — o diff é 100% acréscimo):

| Função | O que faz |
|---|---|
| `executar_ferramenta_mcp(wp_url, user, pwd, tool, params, timeout)` | `POST {wp_url}/wp-json/conexo/v1/mcp/execute` com `{tool, params}`. Retorna `{"ok": True, "result": {...}}` ou `{"erro": ...}`. **Nunca levanta** |
| `publicar_comparativo(contrato, wp_url, user, pwd, timeout)` | valida o contrato, monta os parâmetros e chama `create_comparativo` |

`requests` já era dependência do projeto. **Nenhuma dependência paga, nenhum
serviço novo** — só o endpoint que o próprio site já expõe.

### O que `publicar_comparativo` faz, na ordem

1. `contrato_para_mcp(contrato)` — valida a estrutura **e** roda o gate de
   valor por produto (M04.17A). Contrato inválido → `{"erro": ...}` e **nenhuma
   requisição**;
2. **Fail-closed na fronteira**: se o `content` ainda tiver documento
   completo (`<!DOCTYPE`/`<html`/`<head`), recusa. O defeito de produção do
   review 9183 não passa por aqui;
3. chama o MCP `create_comparativo`;
4. confere a resposta: `post_id` presente e `status == "draft"`. Status
   diferente de `draft` é **erro explícito** (com o `post_id` junto, para o
   post poder ser inspecionado) — não sucesso silencioso.

O MCP fixa `post_status = draft` (`inc-mcp-server.php:288`); a conferência
do passo 4 é cinto-e-suspensório, para o caso de o servidor mudar.

## 4. Testes (20 novos, tudo mockado — nenhum post criado)

**Contrato:** endpoint e ferramenta corretos; os 8 parâmetros no formato
declarado pelo servidor; tabela (`products`/`notas`/`buys`) alinhada;
`content` só com o corpo; cabeçalho de autenticação.

**Regressão do legado:** a assinatura pública de `publicar_no_wordpress` não
mudou (comparação de `inspect.signature`); o legado ainda cria em
`/wp/v2/posts`; `publish` sem `PASS` continua bloqueado e sem requisição;
`UNKNOWN` continua forçando `draft`; `publicar_pagina` continua em
`/wp/v2/pages`.

**Falhas:** contrato sem evidência por produto → erro e **zero requisições**;
documento completo → erro e zero requisições; credencial ausente → erro;
MCP recusa; MCP sem `post_id`; MCP devolve `publish` → erro fechado;
HTTP 500; timeout; resposta não-JSON; exceção de rede.

1. **O pipeline ainda não chama `publicar_comparativo`.** A função existe e
   está testada, mas nada no `pipeline_rss.py`/`pipeline_p0.py` a invoca
   ainda: o fluxo de comparativo do redator não está ligado ao publicador.
   Ligar isso é M04.17D (junto com a posição do gate).
2. **A evidência na origem**: o `price_history` do redator não traz a origem
   do preço, e sem link de marketplace o gate não aceita o preço como
   evidência (pendência do M04.16).
3. **M04.17D** — onde ligar o gate: ligado no caminho RSS, ele bloqueia 7/7
   feeds (medido no M04.16E). `GATE_PUBLICACAO_ENABLED` continua `false`.
4. **O caminho de notícias** segue como estava, com o documento que o
   extrator produzir. A auditoria do M04.16 achou HTML quebrado no review
   9183; verificar se o caminho de notícias também produz documento inteiro
   é trabalho do M04.17D.
