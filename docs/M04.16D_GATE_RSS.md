# M04.16D — Gate de valor no pipeline RSS: o que ele faz, o que ele NÃO faz

Data: 21/10/2026 · Branch: `feat/m0416d-gate-integration` · PR #6 ·
**`GATE_PUBLICACAO_ENABLED` permanece `false` em produção.**

## 1. O que o PR #6 entrega

O gate de valor (regra 14, fail-closed, PR #5) passa a poder rodar dentro de
`pipeline_rss.py`, entre a **extração** e a **reescrita pela IA**:

```
feed → gate de pauta → extração → [GATE DE VALOR, opt-in] → IA → capa → rascunho WP
```

Propriedades garantidas pelos testes de `tests/unit/test_pipeline_rss_gate_p0.py`
(tudo mockado, sem rede, sem LLM, sem WordPress):

1. **Desligado por padrão.** Sem a variável de ambiente, o fluxo é idêntico ao
   anterior. Só `1`, `true`, `yes` ou `on` ligam — qualquer outro valor
   (`0`, `false`, `sim`, `2`, `enabled`) mantém desligado.
2. **Fail-closed.** Erro na validação vira `BLOQUEADO`; o pipeline nunca segue
   para a IA sem prova de que o gate avaliou o conteúdo.
3. **Bloqueio antes do custo.** O gate roda antes da chamada de IA: item
   bloqueado não gasta token e não chega ao WordPress.
4. **Só `APROVADO` prossegue.** `REVISAR` e `BLOQUEADO` interrompem.

## 2. Medição que impede o erro de operação (21/10/2026)

O gate aceita `links=[url_fonte]` — a URL do item do feed. Os 7 feeds de
`FEEDS_PADRAO` são **todos de terceiros** (tecnoblog, canaltech, olhardigital,
adrenaline, gsmarena, 9to5google, sammobile).

O critério `preco_br_data` exige **marketplace**; o critério `fonte_primaria`
exige **fabricante/estudo oficial**. Nenhum dos dois vem de um feed de
notícias — e `tem_cruzamento` não é informado, e não há evidência estruturada
de vídeo nem de medição.

Medição com o caso **mais favorável possível** (texto com preço `R$ 5.999,00`
+ data válida `17/09/2026` + linguagem de medição + link de fabricante citado
no texto):

```
tecnoblog      tecnoblog.net                -> BLOQUEADO
canaltech      canaltech.com.br             -> BLOQUEADO
olhardigital   olhardigital.com.br          -> BLOQUEADO
adrenaline     adrenaline.com.br            -> BLOQUEADO
gsmarena       www.gsmarena.com             -> BLOQUEADO
9to5google     9to5google.com               -> BLOQUEADO
sammobile      www.sammobile.com            -> BLOQUEADO

RESUMO: 7/7 itens de feed seriam BLOQUEADOS com o gate ligado
```

Reexecutável: `python tools/2026-10-21_medir_gate_no_rss.py` (sem rede, sem
LLM, sem WordPress).

**Leitura:** ligado neste ponto, o gate deixa o RSS produzindo **zero**
artigos. Isso não é defeito do gate — é o gate fazendo o trabalho dele. O
conteúdo de um feed de terceiro reescrito **é** "replicated content"
(SQRG 4.6.6: *"Lowest, even if the page assigns credit"*). O produto correto
para esse material é o **digest** (título + veículo + link), não o artigo.

## 3. Consequência operacional

- `GATE_PUBLICACAO_ENABLED` fica **desligado** até existir a etapa que plugue
  o gate no **ponto certo**: depois da coleta de evidência do artigo (preço
  datado em marketplace, medição própria, vídeo transcrito, cruzamento).
- Desligar o gate **não** volta ao estado fail-open: o PR #5 continua no
  `master`, e é a **correção** do gate. O que o PR #6 adiciona é só o ponto de
  chamada opcional.
- A proteção real do caminho RSS hoje é o que já existia: rascunho apenas
  (`status=draft` fixo), sitemap público desativado (`publicar_indice`), e
  `marcar_visto` só depois de o rascunho ser confirmado.
