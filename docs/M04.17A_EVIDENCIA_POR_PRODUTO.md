# M04.17A — Evidência por produto (fecha o 2º requisito do Issue #9)

Data: 21/10/2026 · Branch: `feat/m0417a-evidencia-por-produto` ·
**Sem deploy, sem ativação do gate, sem publicação.**

## 1. O defeito

`filtrar_valor_acrescentado` recebia o **texto inteiro** e varria o conjunto.
Um único preço com data no texto approveva um comparativo de vários produtos:

```
comparativo "Galaxy S26 vs Pixel 11"
texto: "O S26 sai por R$ 5.999,00 em 17/09/2026. O Pixel 11 ainda sem preço."
links: [amazon.com.br/dp/B0XXX]
→ APROVADO  criterios=['preco_br_data']
```

O preço era do S26. O Pixel 11 não tinha preço nenhum — e mesmo assim o
comparativo inteiro passava. Era o 2º critério objetivo do Issue #9 ("exigir
evidência aprovada para cada produto/preço/data/fonte quando pertinente"), e o
que faltava depois do PR #5.

## 2. A regra implementada

> **Evidência de um produto nunca aprova outro.**

Cada produto é avaliado **isoladamente**, com o próprio preço, a própria data,
os próprios links, a própria medição e o próprio vídeo. Nada é herdado do
texto geral nem de outro produto da lista.

No modo por produto o **texto geral não participa do veredito**: se o texto
trouxer um preço que não pertence a nenhum produto, esse preço não aprova
ninguém. Sem essa regra, a contaminação voltaria pela porta do texto.

## 3. Contrato (aditivo — o contrato aprovado no M04.16C não muda)

```python
filtrar_valor_acrescentado(
    ...,                        # tudo igual ao M04.16C
    produtos=None,              # novo: lista de produtos
    exigir_produtos=False,      # novo: sem lista => BLOQUEADO
)
```

Cada produto é um dicionário:

```python
{
  "nome": "Galaxy S26",              # rótulo nos avisos
  "preco": "R$ 5.999,00",            # opcional
  "data_captura": "17/09/2026",      # opcional
  "fonte_preco": "https://www.amazon.com.br/dp/B0XXX",   # opcional
  "links": ["https://news.samsung.com/br/..."],          # opcional
  "fontes_cruzadas": [...],           # opcional
  "tem_cruzamento": True,             # opcional
  "evidencia_video": {...},           # opcional (mesmo formato do M04.16C)
  "evidencia_medicao": {...},         # opcional (mesmo formato do M04.16C)
  "texto": "...",                     # opcional: trecho do produto
}
```

Critérios por produto (cada um calculado **só** com os dados daquele produto):

| Critério | Exige |
|---|---|
| `preco_br_data` | preço **e** data de captura **válida** declarados no produto, e link de **marketplace** conhecido entre os links do produto |
| `fonte_primaria` | link de fonte primária oficial entre os links **do produto** |
| `video_transcrito` | `evidencia_video` do produto (URL válida + transcrição ≥60 palavras) |
| `medicao_propria` | `evidencia_medicao` do produto (método + ≥2 medições completas) |
| `cruzamento_2fontes` | `tem_cruzamento` do produto **e** ≥2 domínios independentes entre os links **do produto** |

**Veredito:** `APROVADO` só se **todos** os produtos tiverem ao menos um
critério. Produto sem critério → `BLOQUEADO` com `motivo="produto_sem_valor"`
e a lista `produtos_sem_valor`.

### Saída nova

| Campo | Significado |
|---|---|
| `evidencia_por_produto` | `"aplicada"` · `"nao_aplicada"` (modo texto) · `"exigida_nao_aplicada"` |
| `criterios_por_produto` | `{nome do produto: [critérios]}` |
| `produtos_sem_valor` | produtos que reprovaram o item |

O modo texto (sem `produtos`) continua existindo e **declara** que a
validação por produto não foi aplicada — a lacuna fica visível em vez de
silenciosa. `exigir_produtos=True` bloqueia quando a lista não vem: é o modo
do fluxo comparativo, onde a lista é obrigatória.

## 4. Exemplo

```python
gate_publicacao(
    titulo="Galaxy S26 vs Pixel 11",
    texto="Comparamos os dois em 30 dias de uso.",
    produtos=[
        {"nome": "Galaxy S26", "preco": "R$ 5.999,00", "data_captura": "17/09/2026",
         "fonte_preco": "https://www.amazon.com.br/dp/B0XXX"},
        {"nome": "Pixel 11", "preco": "R$ 4.299,00", "data_captura": "17/09/2026",
         "fonte_preco": "https://www.mercadolivre.com.br/pixel-11/p/MLB123"},
    ],
)
→ APROVADO  criterios_por_produto={'Galaxy S26': ['preco_br_data'],
                                    'Pixel 11': ['preco_br_data']}
```

Sem o preço do Pixel 11, o mesmo comparativo volta `BLOQUEADO` com
`produtos_sem_valor=['Pixel 11']`.

### Erro meu, correção e trava

O primeiro `_avaliar_por_produto` quebrava com `AttributeError` quando a lista
recebia algo que não fosse dicionário (`'str' object has no attribute 'get'`)
— o nome do produto era lido antes do validador. Corrigido: a extração do
nome agora tolera qualquer tipo, e o validador devolve "produto inválido" como
ausência de critério (bloqueio, não exceção). Trava: entrada malformada vira
**bloqueio**, nunca exceção — exceção num gate fail-closed vira passagem
indesejada em quem chama.
